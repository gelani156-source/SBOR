# СБОР — этап 2: основа облачной базы

Это **не финальная версия**. В архиве только SQL для новой базы Supabase. Действующий сайт GitHub Pages при выполнении SQL **не меняется**.

## Как запустить

1. Создать отдельный **тестовый** проект на https://supabase.com/dashboard.
2. Открыть в нём **SQL Editor → New query**.
3. Скопировать весь файл `01_schema.sql`, вставить и нажать **Run**. Не запускать в базе с существующими реальными таблицами `trips`, `profiles` и т. д.
4. Проверить в **Table Editor** наличие таблиц: `profiles`, `trips`, `trip_members`, `places`, `ideas`, `tasks`, `expenses`, `messages`.
5. На вкладке Authentication настроить провайдеры входа и URL сайта. Подключение к React ещё не сделано.

## Что реализует схема

- поездки и их владельцев;
- участников поездки и базовые роли;
- места маршрута, идеи, задачи, расходы, чат;
- RLS для приватности между разными поездками;
- автоматическое добавление создателя в участники.

## Что намеренно отложено

Публичный просмотр по приглашению, защищённые ссылки с истечением срока, тайное голосование, деление расходов, офлайн-синхронизация, фото, документы и OAuth UI. Нельзя считать их работающими по одному этому SQL.

**Важно:** никакие service_role keys, пароли или секреты не вставлять в GitHub Pages или публичные файлы. В клиенте может использоваться только publishable/anon key при включённой RLS.

При следующем шаге добавим безопасный обмен приглашениями и подключим интерфейс к базе. До настройки авторизации и RLS не публиковать реальные личные данные.
